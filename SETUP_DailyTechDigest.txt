DAILY TECH DIGEST — UPDATED CODE.GS SETUP
Version: 22 October 2026

WHAT THIS VERSION INCLUDES
- Broad daily coverage across 17 areas: AI models, AI products, developer tools/coding agents, open source/GitHub, research, prompt/context engineering, agent evaluations/workflows, cybersecurity/privacy, Big Tech/startups, data science/ML/data engineering, cloud/databases/APIs, web/mobile, hardware/robotics, policy, India tech/startups, automation/project ideas, and consumer devices/telecom.
- Google News RSS across US, UK and India English editions, plus direct RSS/Atom feeds from primary sources and specialist technology outlets.
- A target of 15–20 distinct high-value stories; it deliberately sends fewer if there is not enough fresh, useful news.
- Top 3 developments, Builder's Corner, the rotating Prompt Engineering Lab lesson, and a separate Prompt Engineering Radar that only appears when a recent, non-repeated development passes the rules.
- Recent-story and near-identical headline history, short RSS caching, batched fetches, bounded Gemini retries, and an RSS-only fallback if Gemini is unavailable.
- Multiple recipients: first address in To, additional addresses in BCC.
- Daily trigger around 8:00–9:00 AM Asia/Kolkata.

IMPORTANT LIMITATIONS
- The code was checked for JavaScript syntax and local logic tests (Radar rules, lesson rendering, recent-event duplicate checking, recipient parsing, and HTML/plain-text rendering) passed in a local test harness.
- It has NOT been run inside your Google Apps Script account. Live RSS availability, account permissions, your API key, Gemini quota/access and actual email delivery must still be tested in Apps Script.
- RSS feeds generally provide headlines/excerpts, not complete articles. The digest does not read or verify the full text of every linked article.
- Prompt Engineering Radar is conservative and heuristic. It can miss a genuinely new development or occasionally include an imperfect match; it is not a guarantee of complete monitoring.
- Free-tier model access and usage limits can vary by model, project and current Google policy. Check AI Studio usage/limits. Google currently lists gemini-3.8-flash and gemini-3.5-flash-lite in its model catalogue and pricing page, but the test function in your own project is the practical check: https://ai.google.dev/gemini-api/docs/models and https://ai.google.dev/gemini-api/docs/pricing
- Gemini API free-tier data may be used to improve Google's products. This workflow sends public headlines and short RSS excerpts; do not add private or sensitive content to the Gemini prompt.
- No Google Search grounding is used by this script. It uses RSS discovery and does not add a paid service.

INSTALL OR UPDATE
1. Open your existing Google Apps Script project.
2. Make a backup of your existing Code.gs first (copy it into a local text file).
3. Open Code.gs, select all existing code, and replace it with the full contents of the supplied updated Code.gs file. Save.
4. In Project Settings, set the project time zone to Asia/Kolkata.
5. Open Project Settings > Script Properties and add:
   GEMINI_API_KEY = your Gemini API key
   RECIPIENT_EMAILS = address1@example.com,address2@example.com
   RECIPIENT_EMAILS is recommended. Use comma or semicolon separators. The first recipient is placed in To and the rest in BCC. RECIPIENT_EMAIL is supported as a legacy single-address property, but this public source repository intentionally has no recipient fallback.
6. Keep the API key in Script Properties, not in the source code. Do not paste your API key into chat or logs.

TEST IN THIS ORDER
1. Select testPromptEngineeringLab and click Run. This verifies lesson selection and rendering locally without fetching news, calling Gemini or sending an email.
2. Select testPromptEngineeringRadarRules and click Run. This checks recent-development, stale-item and evergreen-content rules without network calls.
3. Select testGeminiConnection and click Run. This calls Gemini and checks the primary model, then the fallback if needed. A 503 usually indicates temporary capacity; a 429 may indicate a rate limit or quota. Review the execution log and the AI Studio usage page.
4. Select testRssFetch and click Run. This fetches a bounded subset of Google News and direct feeds. It does not send email.
5. Select testDigestNow and click Run. THIS SENDS A TEST EMAIL with [TEST] in the subject. It does not save story history or advance the Prompt Engineering Lab lesson.
6. Inspect the received email. Check source links, story quality, the Prompt Engineering Radar (only if a qualifying new event is found), the daily lesson and Builder's Corner.
7. In Apps Script, open Triggers and confirm whether a sendDailyDigest trigger already exists. If testing is successful and no working trigger exists, select installDailyTrigger and click Run once. That function removes existing sendDailyDigest triggers and creates one daily trigger, so running it again resets the trigger rather than creating duplicates.
8. Review the Executions page after the first scheduled run. It is scheduled for approximately 8:00–9:00 AM IST, not an exact minute.

USEFUL FUNCTIONS
- testPromptEngineeringLab() — local lesson/render test only.
- testPromptEngineeringRadarRules() — local Radar rules test only.
- testGeminiConnection() — tests Gemini access.
- testRssFetch() — fetches a bounded RSS preview; no email.
- testDigestNow() — sends one test email; no history update.
- sendDailyDigest() — main scheduled handler; normally let the trigger call this.
- installDailyTrigger() — installs/resets the daily trigger.
- removeDailyTrigger() — pauses scheduled delivery by removing this script's daily digest trigger.

IF YOU GET AN ERROR
- Gemini model/access/limits: open https://aistudio.google.com/ and review API usage/limits and the selected project's API key.
- Apps Script execution: Extensions / Apps Script > Executions; open the latest failed run and inspect the first error.
- RSS errors: an individual feed can fail and be skipped. If every feed fails, check the execution log and rerun testRssFetch later.
- 503/UNAVAILABLE: temporary server capacity can cause it; the code has bounded retries and falls back to RSS headlines if curation fails.
- 429/quota: check project/model limits in AI Studio rather than repeatedly rerunning the script.
- Email not received: check spam/promotions, verify RECIPIENT_EMAILS, and check MailApp remaining quota in the execution log.

FREE-TIER DESIGN CHOICES
- One primary Gemini curation call on a normal successful run; a fallback model is only tried when the primary fails.
- RSS feeds are collected in batches and short-lived responses are cached for 15 minutes.
- No extra Gemini call is required for the rotating lesson.
- The Radar uses the same candidate batch and same Gemini curation request, then applies local freshness/repetition checks; it does not call Gemini separately.
- RSS-only output remains possible if Gemini is not configured or temporarily unavailable.
- Daily quotas and model access are controlled by Google and can change. See https://developers.google.com/apps-script/guides/services/quotas
